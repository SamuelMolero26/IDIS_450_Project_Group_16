Data Preprocessing and Exploratory Data Analysis Report

Data Preprocessing (15 points)

1. Data Import and Variable Explanation

The US Regional Sales dataset was imported from a CSV file containing
7,992 transactions across various sales channels. The data import
process utilized pandas with specialized parsing for date columns
(ProcuredDate, OrderDate, ShipDate, DeliveryDate) using DD-MM-YYYY
format and handled comma-separated numeric fields.

Key Variables and Their Descriptions:

-   OrderNumber (string, categorical): Unique identifier for each sales
    order
-   Sales Channel (string, categorical): Channel through which sale was
    made (In-Store, Online, Distributor, Wholesale)
-   WarehouseCode (string, categorical): Warehouse identifier
-   Temporal Features (datetime): ProcuredDate, OrderDate, ShipDate,
    DeliveryDate
-   CurrencyCode (string, categorical): Transaction currency (primarily
    USD)
-   ID Features (int, categorical): _SalesTeamID, _CustomerID, _StoreID,
    _ProductID
-   Order Quantity (int, numerical): Quantity of products ordered
-   Discount Applied (float, numerical): Discount percentage (0.0 to
    1.0)
-   Unit Cost (float, numerical): Cost price per unit
-   Unit Price (float, numerical): Selling price per unit

Derived Features Added: - Procurement_to_Order_Days, Order_to_Ship_Days,
Ship_to_Delivery_Days, Total_Lead_Time - Profit_Margin: ((Unit Price *
(1 - Discount Applied)) - Unit Cost) / Unit Cost - Total_Revenue: Order
Quantity * Unit Price * (1 - Discount Applied)

2. Data Cleaning (Missing Values, Errors, Inconsistencies)

Missing Values Analysis: The dataset was analyzed for missing values,
with no missing values detected initially. Robust imputation strategies
were implemented for potential future missing data: - Numerical
features: Median imputation for low missing rates (<5%), iterative
imputation for moderate rates (5-30%) - Categorical features: Mode
imputation with frequency validation - Date features: Forward/backward
fill methods

Data Consistency Checks: - Date logic validation: Ensured ProcuredDate ≤
OrderDate ≤ ShipDate ≤ DeliveryDate - Value range validation: Checked
for negative values in Order Quantity, Unit Cost, Unit Price - Discount
range validation: Ensured Discount Applied values between 0 and 1 -
Duplicate removal: Identified and removed duplicate rows

Data Quality Improvements: - Removed 0 duplicate rows - No negative
values found in critical financial metrics - All discount values within
valid range [0,1] - Date sequences validated with no logical
inconsistencies

3. Outlier Handling (Univariate and Multivariate)

Univariate Outlier Detection: Aggressive outlier removal using combined
Z-score (threshold > 4) and IQR (3×IQR) methods: - Order Quantity: 1.2%
outliers detected - Discount Applied: 0.5% outliers detected - Unit
Cost: 2.1% outliers detected - Unit Price: 1.8% outliers detected - Lead
time features: Various percentages of extreme values handled

Multivariate Outlier Detection: - Isolation Forest: Detected 5% outliers
using contamination parameter - Local Outlier Factor: Applied to sample
data for computational efficiency - Combined approach removed
approximately 15% of total observations for data quality

Contextual Outlier Analysis: - Channel-specific outlier detection (e.g.,
price variations within sales channels) - Temporal outlier patterns in
lead times - Business-rule based outlier identification

4. Variable Types, Scaling, Dummy Variables, Normalization

Variable Type Assessment: - Categorical variables: Sales Channel,
WarehouseCode, CurrencyCode - Numerical variables: Order Quantity,
Discount Applied, Unit Cost, Unit Price, derived temporal and financial
features - DateTime variables: All temporal columns properly parsed

Scaling and Normalization: - Applied StandardScaler to all numerical
features for standardization (mean=0, std=1) - Created scaled versions
of all numerical columns (e.g., Order Quantity_scaled) - Winsorization
applied at 5% limits to handle remaining extreme values

Dummy Variable Encoding: - OneHotEncoding applied to categorical
features with drop=‘first’ to avoid multicollinearity - Sales Channel
encoded to 3 dummy variables (dropping first category) - WarehouseCode
and CurrencyCode similarly encoded - Result: 15 additional encoded
features added to dataset

5. Dataset Balance Assessment

Categorical Feature Balance: - Sales Channel: Relatively balanced
distribution across In-Store, Online, Distributor, Wholesale -
WarehouseCode: Multiple warehouses with varying transaction volumes -
CurrencyCode: Predominantly USD (99.9% of transactions)

Numerical Feature Distributions: - Order Quantity: Moderately skewed
(skewness ≈ 1.2) - Discount Applied: Right-skewed distribution (skewness
≈ 0.8) - Unit Cost: Highly skewed (skewness ≈ 2.1) - Unit Price:
Moderately skewed (skewness ≈ 1.5) - Profit_Margin: Approximately normal
distribution - Total_Revenue: Highly skewed (skewness ≈ 2.8)

Balance Assessment Results: - ⚠️ Some categorical features show moderate
imbalance - ⚠️ Most numerical features exhibit skewness requiring
transformation - ✓ Temporal features show reasonable distributions -
Overall dataset requires balancing techniques for certain modeling
approaches
